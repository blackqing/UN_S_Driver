# UN_S

Windows 用户态与内核态协作的 C++ 研究工程，包含用户端、内核初始化模块和内核功能载荷。

> 本文基于公开源码的静态阅读编写，不代表已经完成编译、运行或兼容性验证。项目涉及内核内存访问、进程操作及载荷执行，仅应在获得授权的隔离测试环境中研究，不应直接用于生产系统。

## 项目结构

| 路径 | 职责 |

## 架构概览

三个模块分别承担调用、初始化和功能执行职责，并非三个可以独立使用的普通应用程序。

- **用户端**：[Main.cpp](UN_UserCode/Main.cpp) 组织主要流程；[UN_Driver.hpp](UN_UserCode/UN_Driver.hpp) 封装与内核侧交互的数据及调用。
- **初始化模块**：[UN_LiteMapper.cpp](UN_LiteMapper/UN_LiteMapper.cpp) 负责内核侧初始化；[Wsk.hpp](UN_LiteMapper/Wsk.hpp) 包含内核网络相关实现。
- **功能载荷**：[UN_Shellcode.cpp](UN_Shellcode/UN_Shellcode.cpp) 为内核功能入口，具体能力拆分到对应头文件。

从源码可见，载荷交付涉及回环 TCP 与内核 WSK；日常请求通过注册表写入触发内核回调，请求结构体包含控制信息及指针。这不是常规的设备 IOCTL 接口，理解和修改前应先核对两端协议及内存生命周期。

## 开发环境

从当前工程配置可确认的依赖包括：

- Windows 开发环境与 Visual Studio 2022 的 C++ 开发组件。
- 用户端使用的 MSVC v143 工具链。
- Windows SDK 与 Windows Driver Kit（WDK）；内核工程指定 Windows 平台版本 `10.0.26100.0`，使用 `WindowsKernelModeDriver10.0` 工具集。
- 工程引用的 MASM 构建组件。

可从 [UN_Driver.sln](UN_Driver.sln) 检查工程与配置映射。解决方案将内核项目映射到 Release x64；部分项目文件虽包含 ARM64 配置，但这不等于源码已支持 ARM64。

用户端 Debug 与 Release 的入口和行为存在区别，不能假定两种配置可以等价替换。构建前应分别检查各项目的入口符号、工具集、包含路径及链接设置。

**本文未执行构建，也未验证驱动签名、部署或载荷加工链。编译成功不代表具备可运行的完整环境。**

## 兼容性与稳定性注意事项

- **系统版本敏感**：内核特征扫描及私有结构依赖可能随 Windows 更新而失效，不能将工程目标版本视为兼容性承诺。
- **指针与生命周期**：跨用户态/内核态传递的指针需要重点检查访问合法性、所属进程、并发访问和对象存活时间。
- **异步网络处理**：需核对 WSK 请求完成、超时及资源释放之间的关系。
- **初始化与错误路径**：需核对握手输出、配置长度以及失败后的清理逻辑，不应依赖未初始化状态。
- **内核故障影响范围大**：错误可能导致系统崩溃或数据损坏；研究时应使用具备快照及内核调试条件的隔离虚拟机。

以上是静态阅读后的关注点，不是完整安全审计结论，也不代表已经确认所有潜在问题的可利用性。
